# 图标 / favicon 的画法标准

来源：skills.sh 上的 `icon-design`、`favicon-gen`（jezweb/claude-skills）与 `svg-logo-designer`（rknall/claude-skills），
提炼成可执行规则。做任何图标（favicon、工具页图标、分享图）都按这套来，不要凭感觉。

## 六条硬标准

1. **网格固定**：32×32 viewBox，内容落在 24×24 安全区（4u 内边距），坐标只落 0.5u。
4u = 16px 下 2 个物理像素，是主笔画的下限。
2. **最小笔画 ≥4u、最小负空间 ≥2u**：低于就简化图元，不要靠缩小细节硬塞。
3. **光学修正**：圆和尖角外扩 0.5u（overshoot）；曲线靠放大形状补偿，不是加粗笔画；
不对称图形按视觉重心而非几何中心对位。
4. **单一剪影**：3–5 个图元，缩到 16px 仍是一瞥可命名的轮廓。靠内部细节成立的方案在标签栏必死。
5. **正负两版都要成立**：单色 fill + `prefers-color-scheme`，反白后剪影一样清楚，
不要靠细线“变粗”续命。深色 favicon 另加 `<link rel="icon" media="(prefers-color-scheme: dark)">` 更稳（Safari）。
6. **先选隐喻再画**：先定要讲的事（写作 / 阅读 / 停留 / 索引），再挑一个能一眼命名的物件；
不为独特而抽象。

## 验收方法

- 16px 光栅化后看两个数：**墨量占比**（实心像素）与**灰边占比**（alpha 0.15–0.75 的抗锯齿像素）。
灰边越低越锐，>10% 基本就糊了。
- 一定要在**浏览器标签模拟**里看 1:1 效果，不要只看 120px 大图。
- 深浅两底各看一眼，确认没有消失、没有糊成一团。

## 本站结论（2026-11）

`patrick12138.github.io` 没有 favicon 时，标签栏显示默认地球。
试过的方向与被否原因：小写 `p`（像 pixiv）、折角纸页 / 缺口方块 / 「」括号 / 句点+横线 / 三条横线 / 层叠方块（都偏“几何残缺”或“线条堆叠”）。
当前候选与评分见 `/var/minis/workspace/icons/v3/preview.html`（a 逗号 / b 书签 / c 脚注星号 / d 对开页 / e 冒号 / f 一笔），
方法论上 b 书签最锐（16px 墨量 29.7%、灰边 3.1%），**最终选用的是 f「一笔」**
（一个撇画，墨量 12.1%、灰边 3.5%）——用户偏好手写感、更像个人签名而不是产品图标。
已落地为仓库根 `favicon.svg`：纯 path、单色、`prefers-color-scheme` 深浅两版，
页面通过 `add_toc.py` 的 `ensure_icon()` 幂等注入（老文章不用整篇重建）。
