2027，是 USER 之年。

AI 终会吃掉所有 verifiable reward。而人心里那些模糊的判断，才将成为最稀缺的资源。去找 user，去学 sales，去 formalize things。

  • 2023：LLM 之年
  • 2024：agent 之年
  • 2025：RL 之年
  • 2026：continual learning 之年
  • 2027：USER 之年

为什么 2027 是 USER 之年？

这篇我犹豫了很久要不要写，因为它会让很多人难受，包括我自己。

过去几个月，我和数不清的人聊过这件事：做 research 的，做产品的，做 infra 的，做投资的。每一次聊完，我都希望自己是错的。但每一次，结论都一样：

所有只跟“事”打交道、不跟“人”打交道的东西，都在迅速贬值。

一个任务只要有 verifiable reward，很快就会被 AI kill 掉，这基本已经成了公理。2026 年 RH 被 kill 了，最难的 verifiable task 基本都做完了。有了 RSI 后，benchmark 差不多四个月就被 kill 一次。通用 agent 能稳定做的事情，价值会慢慢接近 token 的价值。所以现在真正重要的工作，是去 verify “什么东西让人觉得有价值”。

现在模型这么强，你想造个东西（论文、产品、证明，任何数字化的东西）变得极其容易。但反过来，别人想判断你的东西到底有没有价值，也难了很多，因为谁都可以借 agent 更快地刷任何 metric。一个工程师一天能 merge 1000 个 PR，但这说明不了质量。

那现在还有什么 metric 是有效的？我觉得有两个：一是你手里有多少别人拿不到的资源，二是你做的东西对人产生了多大影响。这两样都需要真人花时间或花钱，所以没法凭空生成。

稀缺资源：human judgment

现在最值钱的资源，是只存在于人身上的 context 和 judgment。它大概有三种：

  • 领域专家知识（比如 Yiyou Sun 等人的 Agents' Last Exam，找了 55 个行业的 300 多位专家）
  • 稀缺领域和场景下的 context（比如 bcchen82 的 SwimMate，能同时追踪 3 条泳道、最多 36 名泳者）
  • 足够长时间的 context（从几天到几个月，比如 Yejin Choinka 等人的 Noeri，以及 ysu_nlp 等人的 ApprenticeBench，都是以公司运营为 context 的 agent）

这些东西目前几乎没法从 agent 那里拿到，因为 agent 本来就没有。human judgment 和数学这类 verifiable 的东西不一样：数学不管 AI 用什么方法生成解答，只要最后答案对、能过验证器就行；human judgment 不一样。一个领域里 obvious 的知识，你问 AI 就能了解得很清楚，因为网上有的都已经训进模型了，即便是新内容，很快就会被刷满；而 human judgment 抓住的恰恰是“人有而 AI 没有”的东西。你硬要 AI 生成也可以，但它只会按自己的理解去生成，基本就是自噬。不 obvious 的知识只在人的脑子里，这才是稀有的部分。

所以首先要想的，是怎么拿到这些稀缺的 data。如果一个领域有价值且 Claude 能很轻松地拿到数据，那与其竞争如同螳臂当车。

对人的影响：用户愿意花的时间 × 钱

什么样的影响才真的有价值？简单说：用户愿意投入的时间 × 金钱。

自从我开始想这件事，很多人一直问我：如果 frontier model 有了我想做的能力怎么办？我的回答是，那些和人无关的难题，迟早会被模型攻破；剩下和人有关的难题，目前还极难攻破。就算 frontier model 有知识、有推理能力、有速度，也还是要说服人愿意用，还要找到真正能给这些人带来价值的 use case。这些东西都在 chat 那个屏幕之外。用户打开 Claude，看到的是一句“What do you want to do today?”，而不是他这个领域的 context。这时候，通用 chat 模型就已经输给了垂类产品。

因为垂类产品强的不只是背后那个 LLM。所有配套的、所谓边缘的东西，都会成为打进一群用户的核心优势。为什么 Cursor 当时能火？它背后接的 GPT 也好，Claude 也好，大家拿到的都一样。Cursor 赢在模型之外的东西：它直接 fork 了 VS Code，工程师不用换习惯；它能读到你整个 repo，不用你一段段复制粘贴；改动以 diff 的形式摆在你面前，你可以逐行接受或拒绝；按 Tab 就能补全。今天回头看，这些都很自然，好像本来就该这样。但在 Cursor 之前，大家用的是 ChatGPT 加复制粘贴，也没觉得哪里不对。这些设计每一个都正好贴着 engineer 写 code 时的 sense，可你得真的懂这群人怎么干活，才能想到他们最舒服的用法是什么。换一个人群，答案就完全不一样，而且没有现成的东西可以抄。反过来，你做的东西只要稍微偏离用户的 sense 一点点，他们很快就没耐心了。比如你只想改一行，它却把整个文件重写了一遍。哪怕改得全对，你也得从头再检查一遍，下次就不太想用了。

这里想说的，就是“注意力”和用户真的愿意用的区别。愿意看和愿意用很不一样：用户愿意看，是被吸引过来；用户愿意用，是愿意为你花钱、花资源，这才能留住人。这一点在每个时代都成立。

很多人喜欢追热点，觉得只要在合适的时机发一个好的 release，就能带来巨大的流量。这有它的道理：如果你的受众只打算在你的东西上花几秒到几分钟，那事情越大，越能调动人的情绪，impact 也就越大。但让人看的东西和让人用的东西，区别在于你 overfit 的是什么。前者 fit 的是一个短暂的切面，后者 fit 的是一个高频场景下真实、多样的 dev set。在特定场景下去 fit 用户，AI 自己做不到，因为它跳不出那个屏幕；而你在屏幕外，有没有成功 fit 一个用户群体，就从这个时间 × 金钱的公式里算出来。

Formalization 会有巨大的价值

我觉得接下来最有价值的事情之一，是 formalization：把人心里那些模糊的判断，变成一条条 verifiable reward。这些判断包括觉得一个东西好、觉得一个说法对、觉得一件事值得花时间。

举个例子：“Claude 不说人话”是一个非常难 verify 的判断，没法直接拿来当 reward。“Claude 用'臂'和'腿'这两个词实在太多”能 verify，但就算把这两个词压下去，Claude 也不会因此就说人话了。真正让 Claude 说人话的，是把“不说人话”这种感觉，拆成一条条既能 verify、又真的对齐人类偏好的规则。

再比如做出好用的东西。Claude 能秒做通用的事，但它很难琢磨到那么细：你的东西怎么设计，用户才用得最爽。这件事其实是能量化的。比如用户在你这里完成一件事，心智负担有多小，越小就越好用。现在离把用户体验完全 formalize 还挺远，但我相信，凡是人能明确产生 preference 的事情，背后都是人脑的电信号回路，最终都能被 optimize。

其他 open domain 也需要这种 formalize 的能力，比如判断一篇论文写得好不好，或者一个 research idea 有没有 taste。但 user 是其中反馈最真实的一个：用户用不用你的东西、愿不愿意花时间和钱，都是直接的信号，很难刷出来。

我想跟做研究的朋友说的就是这个。做研究的人习惯从第一性原理出发，去构建并优化 benchmark。这在“优化是个手工活”的时代没有问题。但在今天，优化已经不是瓶颈，真正确定目标才是。为了产生更大的 human impact，反而应该先去找真实的人，搞清楚他们到底觉得什么好，再把这个“好”定义成可以优化的目标。现在 benchmark 四个月就被 kill 一次，后面这种能力只会越来越稀缺。学着理解 user，和学着去做 open domain problem 一样，练的都是能把人的模糊判断变成明确的 verifier。

活得像一个 language model

这也是为什么我觉得“活得像一个 language model”现在这么重要。想学会跟人打交道，最好的参照反而是 AI。它从诞生起做的就是这件事：读人给的 context，猜人想要什么，并从反馈中修正。

比如学会管理 context。给重复性的工作积累 skill，把东西用合适的方式交给 LLM，并且简化自己的 workflow。我发现有了 LLM 之后，很多人的工作量其实在于把东西用合适的方式丢给 LLM，有时候要重复无数次。谁给 LLM 的输入越准、越快、带宽越高，谁能做的事情就越多。

再比如，像 LLM 一样，用概率分析你做的东西里那些细微的差别，它们会让其他人更容易信任你。一个按钮写“Delete”还是写“Delete 3 files”？后者让用户能确认接下来会发生什么，所以用的人会更信任它。

第三，像 LLM-as-judge 一样工作：把你觉得“应该是这样”的东西变成明确的规则。还是采用前面 LLM 说人话的那个例子。因为年初有段时间 LLM 过于不说人话，我之前有次尝试总结出八条规则之后，各家 LLM 基本都正常了（帖子发到 X，有快 100k 的浏览）。这八条最后归结起来其实就一条：人读东西的带宽有限，而 LLM RL 之后会最大化信息密度，所以让 LLM 降低信息密度即可。把“感觉”变成“语言”很难，而这恰恰是 LLM 最吃力的地方，因为 LLM 没有人类的感觉。

Agent 有了正确的 verifier（或者规则、checklist）就能轻松做事，只是没人告诉过它们：在某个具体领域里，感觉对的 verifier 是什么。这就是所谓“老师傅脑子里的经验”，而这些老师傅就是 user。你要是能把它成体系地 formalize，至少也是“Lean for X”的功臣。我猜以后绝大多数 AI native 公司最花力气、最能拉开差距的，就是 formalization 这件事。

去找 user

除此之外，任何围绕 user 建立的 metric 现在都非常有用：用户在你这里花了多少时间，带来了多少 context，这些 context 有多稀有。这些指标就是 human impact 的体现。越来越多人觉得 sales 能力在这个时代越来越值钱：sales 是跟人打交道的。而跟“事”打交道的价值，正在逐渐转移到跟“人”打交道上。换句话说，sales 在 AI 时代是一种 human formalizer：以明确的 reward（如成单）为目标，把人每一点细微的心理变化都成体系地 formalize 下来，再总结出“怎么 take action 才能提高 reward”。

所以：去找 user，去学 sales，去 formalize things。很多人因为 AI 黑盒而产生担忧，但在人心被完全 formalize、能被算法预测之前，人才是 AI 最大的黑盒。而现在，正是把人的经验变成 AI 白盒的最好时机。
