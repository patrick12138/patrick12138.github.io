记录时间：2026-10-22
环境：DSH 0.2.1-rc.2（本机 dsh 已装），profile 目录 %USERPROFILE%\.dsh\profiles\{web,desktop}。

一句话结论：DSH 的官方 DeepSeek 适配器不给你改端点，接自建/本地 DeepSeek 必须走 dsh-llm-pi-ai 的手工 provider 路由（api: openai-completions）。

相关：Agent Harness 版图与个人选型、Tern 架构与插件实践

一、先理解 DSH 的配置模型

  • 启动器：dsh [--profile] <name>，--dump-config 打出组合后的插件树，--dump-config-schema 打 JSON Schema，--patch FILE 加临时 overlay，--from-default-profile 重置 profile。
  • 每个 profile 是一个分层叠加的插件树：bundle 层（package.json 的 dsh.profile.bundles）→ cordis.patch.yml（你的层）→ --patch 的 overlay。
  • cordis.yml 只是空数组入口，官方注释明写 "Edit cordis.patch.yml, not this file"。
  • 用到的相关插件 id（dsh web --dump-config 实测）：
- id: llm                  # @deepseek-ai/dsh-llm，纯服务，不含协议代码
- id: llm-pi-ai            # @deepseek-ai/dsh-llm-pi-ai，pi 的模型层：25+ provider + 自定义端点
- id: llm-deepseek         # @deepseek-ai/dsh-llm-deepseek-api-key，官方 DeepSeek
- id: llm-deepseek-account # 账号登录那套
- id: agent-default-model  # config: { provider: deepseek-official, model: deepseek-flash }

dsh-llm-deepseek-api-key 的配置面只有 apiKeyEnv（默认 DEEPSEEK_API_KEY），端点固定指向 api.deepseek.com —— 这就是为什么不能直接改它来接本地服务。

二、接自建 / 本地 DeepSeek 的完整步骤

1. 把模型起成 OpenAI 兼容服务

vLLM / SGLang / Ollama 都行，关键是 GET {baseURL}/models 能列出来：

python -m vllm.entrypoints.openai.api_server --model deepseek-ai/DeepSeek-V3.2 --port 8000
# 或 Ollama：ollama serve && ollama pull deepseek-v3.2    → http://127.0.0.1:11434/v1
curl -s 127.0.0.1:8000/v1/models

2. 在 profile 的 patch 层声明一条路由

~/.dsh/profiles/web/cordis.patch.yml（数组，追加，别覆盖已有项）：

- id: llm-pi-ai
  name: '@deepseek-ai/dsh-llm-pi-ai'
  config:
    providers:
      local-ds:
        displayName: Local DeepSeek
        api: openai-completions
        baseURL: http://127.0.0.1:8000/v1
        apiKeyEnv: LOCAL_DS_KEY        # 本地无鉴权也要给占位凭据
        compat:
          thinkingFormat: deepseek     # 服务端不认 DeepSeek 的 reasoning 字段就删掉
        models:
          - id: deepseek-v3.2         # 必须与 /v1/models 返回的 id 完全一致
            name: DeepSeek V3.2 (local)
            contextWindow: 131072
            maxTokens: 32768
            reasoningEfforts:
              off:
              high: high

3. 切默认模型（不改也行，可在 GUI 里逐会话选）

- id: agent-default-model
  name: '@deepseek-ai/dsh-agent-default-model'
  config:
    provider: local-ds
    model: deepseek-v3.2

4. 验证

dsh web --dump-config | rg -A14 "local-ds"   # 条目是否并进组合树
dsh web                                      # GUI：Settings → Models 里能看到该路由与模型
dsh web --patch ./local-ds.yml               # 不写 profile、临时试

三、字段与硬约束

字段 默认 说明
api 取已装目录 openai-completions / openai-responses / anthropic-messages
baseURL 取已装目录 该路由所有模型的端点；模型发现走 GET {baseURL}/models（bearer），anthropic-messages 走 x-api-key + anthropic-version
apiKeyEnv 无 凭据引用，配置文件里不放密钥；解析为空报 MISSING_CREDENTIAL
models 取已装目录 手工声明的路由必须非空；列表是整体替换，不是追加
modelOverrides 无 只修个别已装模型的容量/能力，不替换整个目录
compat 目录检测 协议兼容开关，逐路由/逐模型
defaultContextWindow / defaultMaxTokens 262,144 / 32,768 未描述模型的回退值
retryPolicy normal，最多 5 次 由 dsh-llm-retry 执行

必须记住的几条：

  1. 无密钥的本地服务也要占位凭据：apiKeyEnv: LOCAL_DS_KEY + 环境变量 LOCAL_DS_KEY=sk-noop，或 headers: { Authorization: "Bearer sk-noop" }。pi-ai 的 openai-completions 实现强制要有 key/Authorization。
  2. GUI 只列 models 里出现的 id（"GUI 的模型选择与提交要求模型出现在目录中"），id 写错就是选不到/UNKNOWN_MODEL。
  3. models 条目的 id 是请求 id；name 只是显示名。
  4. 自建端点常用开关：compat.thinkingTokenBudgetField: thinking_token_budget（把推理预算塞进指定字段）、compat.vllmPriority: <int>（vLLM 优先级调度，服务端要开）、compat.supportsMaxOutputTokens: false（网关不吃 max_output_tokens）。
  5. reasoningEfforts: false 声明非推理模型；off 不保证关掉推理（协议用"省略字段"表达时就是随服务端默认）。

四、坑

  • 联网搜索 / 抓取会失效：profile 里 searchProvider: deepseek-official、fetchProvider: http，本地端点没有 DeepSeek 的 tools 接口；纯编码不受影响。
  • 两套 profile（web / desktop）要分别加 patch，否则只有一个入口生效。
  • 改完不用重启 GUI：provider 配置在运行时解析（"运行时更改配置"），但写坏会在保存时被拒并点名路由+模型（INVALID_CREDENTIAL / MISSING_CREDENTIAL / UNKNOWN_MODEL / QUOTA / RATE_LIMIT）。
  • GenerateOptions.stop 会被 UNSUPPORTED_OPTION 拒绝（pi-ai 的通用流式层不保证跨提供方）。
  • 字段名随版本变（当前 rc），兜底看包自带中文文档：
    …\npm\node_modules\@deepseek-ai\dsh\node_modules\@deepseek-ai\dsh-llm-pi-ai\README.zh.md

五、和 Pi 的关系（为什么这条路成立）

DSH 没有另写 provider 抽象，直接复用了 Pi 的模型层（dsh-llm-pi-ai）。所以 Pi 能接的（Ollama、vLLM、OpenRouter、自定义 OpenAI 兼容端点、切模型），DSH 这条路由也能接；反过来，官方 DeepSeek 原生适配器只在跑 V4 Pro / Flash 时才有优势（它懂 DeepSeek 的协议细节）。
